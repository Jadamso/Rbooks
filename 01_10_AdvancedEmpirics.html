10  Advanced Empirics

The tools in this chapter extend the univariate toolkit but sit outside the main path from data to inference. Each section stands on its own, so you can read them in any order.

This chapter asks three questions.

  • How can we draw a distribution as a smooth curve?
    • Kernel density: this is a new estimate that replaces the fixed bins of a histogram with a moving window of half-width \(h\).
  • What happens when we transform a variable?
    • Data transformations: these reshape a variable before modeling it, and the Box–Cox transform nests many common cases.
    • Jensen’s inequality: this says how the mean of transformed data relates to the transformed mean, as we saw for logged data in LOTUS.
  • How can we generate random draws from a distribution?
    • Inverse sampling: this feeds uniform probabilities through a quantile function, for either an empirical or a theoretical distribution.

10.1 Kernel Density

When we want a smoother picture than the jagged steps of a histogram, we replace fixed bins with a moving window centered on each value of \(x\) we want to evaluate.

A kernel density estimates the density at \(x\) by averaging a smooth weight function (the kernel) centered on each data point, with a bandwidth \(h\) that controls how wide the weight spreads (Rosenblatt 1956; Parzen 1962; Silverman 1986). The bandwidth is a half-width, exactly as in the histogram: each kernel below weights observations within \(h\) of \(x\) and gives zero weight beyond. Unlike the histogram, the bins around each \(x\) can overlap, which is why the result is smooth instead of stepped.

Kernel densities are useful for showing the shape of a distribution as a smooth curve. A curve can be easier to read than a histogram, especially when we overlay two or three distributions on the same axes. Stacked or overlapping bars quickly become hard to tell apart. Kernel densities also extend to two dimensions, where they show how points spread across a map (Scott 2015). Different kernels weight nearby points in different ways. The resulting curves look slightly different, but their overall shapes are similar. The simplest kernel function is the “uniform” (or “rectangular”) kernel, which places a weight of \(1/2\) on every point inside the interval \(\left[ x-h, x + h\right]\) and zero outside: \[\begin{aligned} k_{U}\left( \hat{x}_{i}, x, h \right) &= \frac{\mathbf{1}\left(\frac{|\hat{x}_{i}-x|}{h} \leq 1\right)}{2} = \frac{\mathbf{1}\left( \hat{x}_{i}~\text{in}~\left[ x-h, x + h\right] \right) }{2} \\ \hat{f}_{U}(x) &= \frac{1}{nh} \sum_{i}^{n} k_{U}(\hat{x}_{i}, x, h) = \frac{ \sum_{i}^{n} \mathbf{1}\left( \hat{x}_{i}~\text{in}~\left[ x-h, x + h\right] \right) }{n 2 h} \end{aligned}\]

For example, take the dataset \(\{3, 3.1, 0.02\}\) with bandwidth \(h=1/2\) and evaluate the density at \(x=3\). The interval \([x-h, x+h]=[2.5, 3.5]\) contains the two points \(3\) and \(3.1\), so \(\sum_{i}\mathbf{1}\left(\hat{x}_{i}~\text{in}~[2.5,3.5]\right)=2\) and \(\hat{f}_{U}(3)=\frac{2}{n 2h}=\frac{2}{3\times 1}=2/3\).

Notice that the uniform kernel is essentially the histogram but without the restriction that \(x\) must be a midpoint of exclusive bins. Typically, the points \(x\) are chosen to be either the unique observations or some equidistant set of “design points” (e.g., at \(512\) evenly spaced values of \(x\) spanning the dataset, not just the midpoints of exclusive bins).1

Code 
## MAIN EXAMPLE
# Practical Example
data(Wages1, package='Ecdat')
x_hat <- Wages1[, 'wage'] # lab data: hourly wages in 1980 dollars
# The axis stops just past 20 dollars, so the 16 largest wages are not drawn
hist(x_hat,
    breaks=seq(0, 40, by=1), # bin width =1, so h=1/2
    xlim=c(0, 20),
    freq=FALSE,
    border=NA,
    main=NA,
    xlab='Hourly wage (1980 dollars)')
title('Hourly Wages', font.main=1)
# Density Estimate with half-width h=1
# 'density' reads bw as the kernel's standard deviation, so pass bw=h/sqrt(3)
h <- 1
f_hat <- density(x_hat, bw=h/sqrt(3), kernel='rectangular')
lines(f_hat)
# Raw Observations, nearly transparent since thousands of marks overlap
rug(x_hat[x_hat <= 20], col=grey(0, .1))

# Kernel Density Functions

x <- 0 # Design point
x_values <- seq(-2, 2, length.out=1001) # Where to compute weight

d_unif <- function(x_values, x, h){
    u <- abs(x_values-x)/h
    fu <- 1/2*(u <= 1)
    return(fu)
}
kU <- d_unif(x_values, x, h)
kern_cols <- c(rgb(.8, 0, 0, .5), rgb(0, .8, 0, .5), rgb(0, 0, .8, .5))
lines( kU ~ x_values, col=kern_cols[1], lty=1)

## Epanechnikov
d_epan <- function(x_values, x, h){
    u <- abs(x_values-x)/h
    fu <- 3/4*(1-u^2)*(u <= 1)
    return(fu)
}
kE <- d_epan(x_values, x, h)
lines( kE ~ x_values, col=kern_cols[2], lty=1)

    u <- abs(x_values-x)/h

10.2 Data Transformations

Transformations can stabilize variance, reduce skewness, and make model errors closer to Gaussian.

The simplest transformation is a change of units, and standardizing is a special case. Suppose each observation is transformed to \(\hat{y}_{i}=a+b\hat{x}_{i}\) for constants \(a\) and \(b\), and write \(\hat{m}_{X}, \hat{s}_{X}\) and \(\hat{m}_{Y}, \hat{s}_{Y}\) for the means and standard deviations before and after. Then \[\begin{aligned} \hat{m}_{Y} &= a + b\hat{m}_{X}, \\ \hat{s}_{Y} &= |b|\hat{s}_{X}. \end{aligned}\] Adding \(a\) moves every observation, and so the mean, by the same amount, but leaves the distances between observations unchanged. Multiplying by \(b\) stretches those distances, so it scales both the mean and the standard deviation. Standardizing sets \(b=1/\hat{s}_{X}\) and \(a=-\hat{m}_{X}/\hat{s}_{X}\), so that \(\hat{m}_{Z}=-\hat{m}_{X}/\hat{s}_{X}+\hat{m}_{X}/\hat{s}_{X}=0\) and \(\hat{s}_{Z}=\hat{s}_{X}/\hat{s}_{X}=1\).

TipTest Yourself

Suppose three workers earn hourly wages of \(\{15, 20, 25\}\) dollars. Each works \(2000\) hours a year and receives a bonus of \(1000\) dollars. Use the change-of-units rules to compute the mean and standard deviation of their annual earnings.

The wages have \(\hat{m}_{X}=20\) and \(\hat{s}_{X}=\sqrt{[25+0+25]/3}=\sqrt{50/3}\approx 4.08\). Annual earnings are \(\hat{y}_{i}=1000+2000\hat{x}_{i}\), which are \(\{31000, 41000, 51000\}\). Then \(\hat{m}_{Y}=1000+2000 \times 20 = 41000\) and \(\hat{s}_{Y}=2000 \sqrt{50/3} \approx 8165\). The bonus raises every worker’s earnings by the same amount, so it does not change the spread.

Code 
x0_hat <- c(15, 20, 25) # hourly wages
y0_hat <- 1000 + 2000*x0_hat # annual earnings with a bonus
y0_hat
## [1] 31000 41000 51000

# mean: shifted by the bonus and scaled by the hours
mean(y0_hat)
## [1] 41000
1000 + 2000*mean(x0_hat)
## [1] 41000

# standard deviation: scaled by the hours only
sqrt(mean((y0_hat - mean(y0_hat))^2))
## [1] 8164.966
2000*sqrt(mean((x0_hat - mean(x0_hat))^2))
## [1] 8164.966
TipTest Yourself

Show that \(\hat{m}_{Y}=a+b\hat{m}_{X}\) and \(\hat{s}_{Y}=|b|\hat{s}_{X}\).

Substituting \(\hat{y}_{i}=a+b\hat{x}_{i}\) into the definitions of the mean and variance, \[\begin{aligned} \hat{m}_{Y} &= \frac{1}{n}\sum_{i=1}^{n} (a+b\hat{x}_{i}) = a + b\frac{1}{n}\sum_{i=1}^{n} \hat{x}_{i} = a + b\hat{m}_{X}, \\ \hat{v}_{Y} &= \frac{1}{n}\sum_{i=1}^{n} (a+b\hat{x}_{i} - a - b\hat{m}_{X})^2 = b^2 \frac{1}{n}\sum_{i=1}^{n} (\hat{x}_{i} - \hat{m}_{X})^2 = b^2\hat{v}_{X}. \end{aligned}\] Taking square roots gives \(\hat{s}_{Y}=|b|\hat{s}_{X}\).

Perhaps the most common examples are power transformations: \(y= x^\lambda\), which includes \(\sqrt{x}\) and \(x^2\).

Other examples include the exponential transformation: \(y=\exp(x)\) for any \(x~\text{in}~(-\infty, \infty)\) and logarithmic transformation: \(y=\log(x)\) for any \(x>0\). The log is undefined at zero, which is a problem for counts. A common fix is to add one before taking logs, so that zero counts get a value of zero (Bartlett 1947). The added one is arbitrary, and results based on the transformed values can change with the units of the count (Bellemare and Wichman 2020; Chen and Roth 2024).

The Box–Cox Transform (Box and Cox 1964) nests many cases used by statisticians. For \(x>0\) and parameter \(\lambda\), \[ y=\begin{cases} \dfrac{x^\lambda-1}{\lambda}, & \lambda\neq 0,\\ \log\left(x\right) & \lambda=0. \end{cases} \] This function is continuous over \(\lambda\).

Code 
## MAIN EXAMPLE
# Box–Cox transform and inverse
bc_transform <- function(x_hat, lambda) {
  if (any(x_hat <= 0)) stop('Box-Cox requires x > 0')
  if (abs(lambda) < 1e-8) log(x_hat) else (x_hat^lambda - 1)/lambda
}
bc_inverse <- function(t, lambda) {
  if (abs(lambda) < 1e-8) exp(t) else (lambda*t + 1)^(1/lambda)
}

hist(x_hat, breaks=seq(0, 40, by=1), main=NA, border=NA, freq=FALSE,
    xlab='Hourly wage (1980 dollars)')
rug(x_hat, col=grey(0, .1))
Code 
# Wages are right-skewed, with 18 above 20 dollars.

par(mfrow=c(1, 3))
for(lambda in c(-1, 0, 1)){
    y_hat <- bc_transform(x_hat, lambda)
    hist(y_hat, breaks=25,
        main=NA,
        border=NA, freq=FALSE)
    rug(y_hat, col=grey(0, .1))
    title(bquote(paste(lambda, '=', .(lambda))), font.main=1)
}
Code 
# lambda=1 only shifts wages, so it keeps the long right tail.
# lambda=0 pulls in that tail, but stretches out the few wages near zero.
# lambda=-1 stretches them further, so about 93% of workers fall in one bar.

Be careful about transforming your data, as the interpretation can be harder.

The mean of transformed data is not equivalent to transforming the mean, for example, which is one reason why you want to first summarize your data before transforming it.

Jensen’s inequality

We can actually say more about how the mean of transformed data is not equivalent to transforming the mean, which we saw for logged data in LOTUS. To do that, we define two types of functions:

  • Concave functions curve inwards, like the inside of a cave.
  • Convex functions curve outward, the opposite of concave.

Let \(\hat{y}_{i}=g( \hat{x}_{i})\), and denote the mean as \(\hat{m}_{Y}\).

If \(g\) is a concave function, then \(g( \hat{m}_{X} ) \geq \hat{m}_{Y}\) (Jensen 1906). The square root and the log are both concave.

Code 
## MAIN EXAMPLE
# Concave: mean of the transform vs transform of the mean
mean( sqrt(x_hat) )
## [1] 2.310261
sqrt( mean(x_hat) )
## [1] 2.399497

# Every wage is positive, so we can take logs of them all.
mean( log(x_hat) )
## [1] 1.587268
log( mean(x_hat) )
## [1] 1.750518

10.3 Drawing Samples

To generate a random variable from known distributions, you can use some type of physical machine. E.g., you can roll a fair die to generate Discrete Uniform data or you can roll weighted die to generate Categorical data.

There are also several ways to computationally generate random variables from a probability distribution. Perhaps the most common one is inverse sampling. To generate a random variable using inverse sampling, first sample \(p\) from a uniform distribution and then find the associated quantile via the quantile function \(\hat{F}^{-1}(p)\).2

Empirically

You can generate a random variable from a known empirical distribution. Inverse sampling randomly selects observations from the dataset with equal probabilities. To implement this, we

  • order the data and associate each observation with an ECDF value
  • draw \(p~\text{in}~[0,1]\) as a uniform random variable
  • find the associated quantile via the ECDF

Here is an example of generating random draws from the lab data.

Code 
## MAIN EXAMPLE
# Empirical Distribution
F_hat <- ecdf(x_hat)
# The axis stops just past 20 dollars, so the 16 largest wages are not drawn
plot(F_hat, lwd=2, xlim=c(0, 20),
    do.points=FALSE, verticals=TRUE, main=NA,
    xlab='Hourly wage (1980 dollars)', ylab='Proportion of workers')
Code 
# With 3294 workers, most jumps are too small to see.

# Generating random variables via inverse ECDF
p <- runif(3000) ## Multiple Draws
x_sim <- quantile(F_hat, p, type=1)
x_sim[c(1, 2, 3)]
## 26.55086631% 37.21238996% 57.28533634% 
##     3.693892     4.387105     5.712490

## Can also do directly from the data
x_sim <- quantile(x_hat, p, type=1)
x_sim[c(1, 2, 3)]
## 26.55086631% 37.21238996% 57.28533634% 
##     3.693892     4.387105     5.712490

Every draw is one of the observed values, since the ECDF only jumps at the data.

If you know the distribution function that generates the data, then you can derive the quantile function and do inverse sampling. That is how computers generate random data from a distribution.

NoteMust Know

Here is an in-depth example of the Dagum distribution (Dagum 1977). The distribution function is \(F(x)=(1+(x/b)^{-a})^{-c}\). For a given probability \(p\), we can then solve for the quantile as \[F^{-1}(p)=\frac{ b p^{\frac{1}{ac}} }{(1-p^{1/c})^{1/a}}\] After which, we sample \(p\) from a uniform distribution and then find the associated quantile.

Code 
# Theoretical Quantile Function (from VGAM::qdagum)
qdagum <- function(p, scale.b=1, shape1.a, shape2.c) {
  # Quantile function (theoretically derived from the CDF)
  ans <- scale.b * (expm1(-log(p) / shape2.c))^(-1 / shape1.a)
  # Special known cases
  ans[p == 0] <- 0
  ans[p == 1] <- Inf
  # Safety Checks
  ans[p < 0] <- NaN
  ans[p > 1] <- NaN
  if(scale.b <= 0 | shape1.a <= 0 | shape2.c <= 0){ ans <- ans*NaN }
  # Return
  return(ans)
}

# Generate Random Variables (VGAM::rdagum)
rdagum <-function(n, scale.b=1, shape1.a, shape2.c){
    p <- runif(n) # generate random probabilities
    x_sim <- qdagum(p, scale.b=scale.b, shape1.a=shape1.a, shape2.c=shape2.c) #find the inverses
    return(x_sim)
}

# Example
x_sim <- rdagum(3000, 1, 3, 1)
x_sim[c(1, 2, 3)]
## [1] 1.3102859 0.4889961 1.2593625

Recall

This chapter covered three more univariate tools. The kernel density smooths a histogram by averaging a weight function centered on each observation with half-width \(h\). Data transformations include the log and the Box–Cox family, and Jensen’s inequality compares the mean of transformed data to the transformed mean. Inverse sampling generates random draws by feeding uniform probabilities through a quantile function. For the first, take the three-point dataset \(\{3, 3.1, 0.02\}\) with half-width \(h=1/2\). Two points fall inside the interval \([2.5, 3.5]\) around \(x=3\), so the uniform kernel density there is \(2/(3 \times 1)=2/3\). For the second, mean(sqrt(x_hat)) is never larger than sqrt(mean(x_hat)) because the square root is concave, and the inequality flips for a convex function like the exponential.

The density function scales its bw argument to be the standard deviation of the kernel rather than the half-width, so bw and \(h\) are different numbers. Setting bw from \(h\), rather than reading \(h\) off bw, keeps the code matching the math. The conversion is a constant that depends on the kernel: the half-width is \(\sqrt{3}\) times bw for the rectangular kernel and \(\sqrt{5}\) times bw for the Epanechnikov kernel (Epanechnikov 1969).↩︎
